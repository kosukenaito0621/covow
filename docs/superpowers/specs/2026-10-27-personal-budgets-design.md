# 人ごとの予算と割り勘（設計書）

2026-10-27 オーナーとの相談で決めた内容。

## 1. 目的

- 今は「スペース全体で1つの予算」。これを**人ごとの予算**にする。お互いの予算・支出・残りは見られるが、**集計は人ごとに独立**させる。
- ふたりで買うもの（折半）は、**割合で分けて、それぞれの支出に入れる**（初期値 5:5）。
- 予定・支出を**人と状態で絞り込める**ようにする。
- うまくいった状態：ふたりがそれぞれ「自分のあと使える金額」を見て使い方を決められ、相手の様子も切り替えて見られる。折半の買い物が、両方の残りに正しく半分ずつ反映される。

## 2. 決まったこと

| 項目 | 決定 |
|---|---|
| 共通の予算（共通の財布） | **持たない**。すべて個人の予算（案 A） |
| 折半の入れ方 | **割合**で入れる。10%きざみ、初期値 5:5 |
| まだ買っていない予定 | **予定の段階で**「誰が払うか・割合」を決め、その人の「あと使える金額」から前もって引く（案 A） |
| 今のスペースの予算 | 同じ金額を**ふたりそれぞれ**の予算にする（例：10月 ¥50,000 → 2人とも ¥50,000）（案 B） |
| 今ある予定・支出 | **登録した人が 100%** 払ったものとして引き継ぐ（旧アプリから移したものは宣言者） |
| データの持ち方 | 予定・支出に「払う人・分ける相手・払う人の割合」の欄を足す（案 B）。**分けられる相手は1人まで**。人数が増えて必要になったら、分担を別の表に持つ形（案 A）に切り替える |
| 予算を変えられる人 | **本人だけ**。相手の予算は見るだけ |
| 絞り込み | 予定：状態＋人。支出：人＋「予定から／予定外」 |

## 3. お金の持ち方

### 3.1 予定・支出に足す欄

| 欄 | 意味 | 値 |
|---|---|---|
| `payer_user_id` | 払う人 | スペースのメンバー。今あるデータは予定＝`created_by`、支出＝`recorded_by` を入れる |
| `split_user_id` | 分ける相手 | NULL＝分けない。払う人と同じ人は不可 |
| `payer_ratio` | 払う人の割合（%） | 10〜100 の 10 きざみ。分けないときは 100、分けるときは 10〜90 |

- DB の制約で守る：割合は 10 きざみ・範囲内、「分けない ⇔ 割合 100」、払う人 ≠ 分ける相手。
- 払う人・分ける相手は、保存するときにスペースのメンバーであることを確かめる（今のカテゴリの確認と同じ場所、`repo/` で）。
- あとでメンバーが抜けても、記録はそのまま残す（集計では「元メンバー」の分として扱う。今と同じ考え方）。
- 予定の「担当」（`assignee_user_id`）は、登録画面では「払う人」に置き換える。列は消さずに残し、使わない（消すとデータの作り直しが必要になるため）。

### 3.2 円の端数

- 金額 × 割合で 1円未満が出たら、**割合の大きい人**に1円を寄せる。同じ割合なら**払う人**に寄せる。2人の合計は必ず元の金額と一致する。
- 例：¥999 を 5:5 → 払う人 ¥500・相手 ¥499。¥1,000 を 3:7 → 払う人 ¥300・相手 ¥700。
- 計算は `src/shared/money/` に1か所だけ置く（`userShare(record, userId)` のような関数。分析の `shareOf`〔割合〕とは別）。サーバーも画面もこれを使う。

### 3.3 予定から支出へ

- 予定を「買った」にするとき、予定の払う人・相手・割合を支出に引き継ぐ。「買った」画面で変えることもできる。
- 「予定に戻す」ときは支出が消えるので、消す前に支出の払う人・相手・割合を予定に書き戻す。

### 3.4 予算

- 予算を「スペース×月」ごとから「スペース×**人**×月」ごとにする。
- 今の予算は、そのときのメンバー全員に同じ金額でコピーする（移行は1回だけ）。
- あとから参加した人の予算は「未設定」から始める。
- 「来月以降も同じ金額にする」（12か月先まで）は、本人の予算にだけ働く。

## 4. 画面

### 4.1 ホーム

- 上に**人の切り替え**（自分／相手…）。開いたときは自分。メンバーが1人なら出さない。
- あと使える金額 ＝ その人の予算 − その人の分の支出 − その人の分の未購入の予定。
- 今月の支出・予定・使用率・週のグラフも、その人の分で出す。
- これから買う予定：その人が払う人か分ける相手の予定だけ。
- 相手に切り替えているときは、予算の行を押しても変えられない（見るだけ）。

### 4.2 予定・支出の登録

- 「払う人」の欄：自分／相手（メンバーの名前）／ふたりで分ける。
- 「ふたりで分ける」を選ぶと、相手（2人なら自動で決まる。3〜4人なら選ぶ）と割合（10%きざみ）を選べる。
- 割合を変えると、それぞれの金額をその場で出す（例：自分 ¥6,000・相手 ¥4,000）。

### 4.3 予定の詳細・「買った」画面

- 払う人と割合（金額つき）を出す。「買った」画面で割合を変えられる。

### 4.4 分析

- ホームと同じ人の切り替えを置き、すべてのタブをその人の分で集計する。
- メンバーのタブ：メンバーごとに「その人の分の支出 ÷ その人の予算」を並べる。

### 4.5 一覧と絞り込み

- 予定一覧：今の状態（すべて／未購入／購入済み／キャンセル）に加えて、人（全員／自分／相手）。
- 支出一覧：人（全員／自分／相手）と、予定から／予定外。
- 人で絞り込んだとき、分けたものは**どちらの人でも出す**。
- 金額は品物の値段のまま出し、分けたものには「折半 自分 ¥5,000」のような小さな印を付ける。

### 4.6 設定

- 予算の欄は自分の予算だけ（今と同じ見た目）。

## 5. サーバー（API）

- `GET /api/summary?month=&user=`、`GET /api/daily?from=&to=&user=`、`GET /api/insights?month=&user=`：`user` を省くと自分。スペースのメンバー（元メンバーを含む）以外を指定したら 404。
- `GET /api/budgets?from=&to=&user=`：見るのは誰の分でも可。`PUT /api/budgets/:yearMonth`：**自分の予算だけ**変えられる。
- 予定・支出の作成・変更：`payerUserId`・`splitUserId`・`payerRatio` を受け付ける（省いたら自分が 100%）。
- 権限の確認は今と同じく `require-member.ts` と `repo/` の2か所だけで行う。

## 6. 移行（本番のデータ）

1. 予定・支出に3つの欄を足し、今あるデータを「登録した人が 100%」で埋める。
2. 予算の表を「人ごと」の形に作り直し、今の予算をメンバー全員にコピーする（予算の表はほかの表から参照されていないので、作り直しても消えるデータはない）。
3. 本番に当てる前に、D1 の復元ポイントを記録する。当てたあと、件数・金額・人ごとの予算を確かめる。
4. **本番への移行とデプロイは、オーナーの許可を取ってから行う。**

## 7. テスト

- 割合の計算（端数の寄せ方、合計が元の金額と一致する）を、いろいろな金額・割合で確かめる。
- 人ごとの集計：折半の予定・支出が、両方の残りに正しく入る。分けていないものは本人だけに入る。
- 予算：自分の予算しか変えられない（相手の予算を変えようとすると 403）。相手の予算は見られる。
- 払う人・分ける相手がメンバーでないと 422。割合が範囲外・10 きざみでないと 422。
- 予定→支出で割合が引き継がれる。予定に戻すと支出の割合が予定に戻る。
- 移行：今あるデータが「登録した人が 100%」になり、予算がメンバー全員にコピーされる。
- ほかのスペースのデータに、どのルートからも触れない（今の権限テストに人の指定を足す）。

## 8. 今回やらないこと

- 3人以上での分担（案 A に切り替えるときに対応）。
- 精算（「どちらがいくら多く払っているか」を出して、差額を清算する機能）。必要になったら別に相談する。
- 共通の予算。
