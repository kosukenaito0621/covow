# 旧アプリ（僕らの宣言帳）のデータを入れる手順

旧アプリから書き出した CSV を、COVOW のスペースに入れる。道具は `scripts/import-legacy.mjs`。

- **CSV（実データ）と、作った SQL はリポジトリに入れない。** パソコンの中から読み、リポジトリの外に書き出す。終わったら SQL は消す。
- 本番に入れるのは「本番のデータに影響する操作」なので、**実行の直前にオーナーの許可を取る。**
- 実際のアカウント・件数・合計などの具体的な情報は、Git に入らない `.private/LEGACY_IMPORT_PRIVATE.md` に書く。

## 入れ方（2026-10-26 に決めた方針）
| 旧アプリ | COVOW |
|---|---|
| 状態「宣言中」 | 未購入の予定 |
| 状態「購入済」 | 購入済みの予定＋支出（実際の金額は予定金額と同じ。買った日は予定日、空なら登録日） |
| 宣言者 | その人のアカウントの記録（2人ともスペースのメンバーであること） |
| カテゴリ | 同じ名前のカテゴリ。スペースになければ足す |
| メモ・購入理由 | メモ |

- 2人とも同じスペースのメンバーでなければ、何も入らない（SQL の条件で守る）。
- ID は旧アプリの ID から作るので、同じ CSV を2回入れても二重にならない。

## 手順（本番の公開後）
1. 1人目（CSV の宣言者）が本番の COVOW に Google でログインし、スペースを作る
2. 2人目を招待リンクで招き、ログインして参加してもらう
3. ふたりのメールアドレスを確認する（設定画面のプロフィールに出る）
4. SQL を作る（件数と合計だけが表示される）
   ```
   node scripts/import-legacy.mjs <CSVのパス> <リポジトリの外のSQLのパス> <宣言者名1>=<メール1> <宣言者名2>=<メール2>
   ```
5. **オーナーの許可を取ってから**、本番に入れる
   ```
   npx wrangler d1 execute covow-db --remote --env production --file <SQLのパス>
   ```
6. 画面で件数と金額を確かめる（期待する値は手順4の表示と、.private のメモ）
7. SQL のファイルを消す

## 開発用での確認（2026-10-26）
テスト用の2人（legacy-a / legacy-b@example.test）のスペースで、実際の CSV を使って試し、次を確認した。
- 件数・購入済みの合計・2人目の件数が CSV と一致する
- 足りないカテゴリが足され、未分類になる予定はない
- 2回入れても増えない
- 2人目が別のスペースの人だと、何も入らない
